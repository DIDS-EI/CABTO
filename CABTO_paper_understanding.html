一句话总结

这篇论文在解决什么？

已有的 BT 规划（BT Planning）能提供"可证明成功"的行为树，但它有一个被默认忽视的前提：它假设一个"已经落地好"的 BT 系统早已存在——即高层动作模型与底层控制策略都已由专家手工设计完毕。CABTO 把"如何自动造出这个系统"本身定义为一个可求解的问题（BT Grounding），并用 LLM/VLM 作为启发式搜索器去高效求解。

问问题

形式化定义 BT Grounding：为给定任务集自动构造一个完备 + 一致的 BT 系统 Φ=⟨C, A⟩。给出朴素穷举算法并分析其 O(2³ⁿ) 指数复杂度。

法方法

CABTO 三阶段：LLM 提议高层动作模型 → VLM 采样底层控制策略 → 跨层精化不一致的动作模型。多模态上下文反馈贯穿全程，规避穷举。

验验证

7 任务集 × 3 平台（单臂/双臂 Franka、移动 Fetch）。规划上下文反馈让 GPT-4o 的系统完备率从 50% 升至 90%+；跨层精化把不一致动作的修正成功率从 12% 提至 74%。

Problem Formulation

BT Grounding 问题的形式化

论文沿用 Cai et al. (2021) 的形式化：一个 BT 系统记作 Φ = ⟨C, A⟩。每个动作 a ∈ A 是一个二元组 ⟨hₐ, πₐ⟩：

  • 动作模型 hₐ（意图效果）：STRIPS 式三元组 ⟨pre, add, del⟩——前置条件、添加效果、删除效果，这是高层规划用的"蓝图"。
  • 控制策略 πₐ（实际效果）：底层真正执行后造成的状态变化。
  • C：所有条件节点的集合（状态由这些二元命题描述）。
sₜ₊ₖ = hₐ(sₜ) = πₐ(sₜ) = sₜ ∪ add(a) \ del(a) 理想：意图 = 实际

即在一个"良好设计"的 BT 系统里，只要当前状态满足前置条件，动作模型预测的状态转移要与策略实际造成的转移完全一致。围绕这一点，论文定义两条关键性质：

Def 0.1 · 完备性 Completeness

对任务集 P 中每一个任务 p，任何「可靠且完备」的 BT 规划算法都能仅依据系统的动作模型生成一棵解决 p 的行为树。

→ 衡量 C 与 A 在"规划层"是否够用。例：动作集 {a₂,a₃} 只能解 {p₂,p₃} ⇒ 不完备；{a₁,a₂} 能解全部三任务 ⇒ 完备。

Def 0.2 · 一致性 Consistency

动作 a 一致 ⟺ preπ ⊆ preₕ 且 addπ = addₕ 且 delπ = delₕ。即底层策略真能造出动作模型声称的状态转移。

→ 衡量"执行层"是否名副其实。例：a₁ 声称 Holding(apple) 但策略抓不起来 ⇒ 不一致；a₂ 没写 IsOpen(drawer) 前置就放抽屉 ⇒ 不一致。

Problem 1 · BT Grounding

给定四元组 ⟨P, C_P, H_P, Π_P⟩（任务集、合法条件节点集、合法动作模型集、合法控制策略集），求一个在 P 上同时完备且一致的 BT 系统 Φ=⟨C, A⟩，其中 C⊆C_P，每个 a=⟨hₐ,πₐ⟩ 满足 hₐ∈H_P, πₐ∈Π_P。

为什么不能直接穷举？

论文给出朴素算法（Algorithm 1）：遍历 pre/add/del 的所有幂集组合枚举动作模型，逐一验证合法性与策略一致性。它正确但不可用——即便只施加 add∩del=∅ 这类领域无关约束，搜索动作模型空间也是 O(2³ⁿ) 的指数复杂度；更何况"自动合成底层控制策略以达成特定效果"本身就是机器人学中尚未解决的根本难题。这正是 CABTO 用大模型做启发式搜索的动机。

The CABTO Framework

三阶段：让大模型在上下文反馈中搜索

CABTO 把落地过程拆成三个阶段，分别用规划上下文、执行上下文、跨层上下文引导大模型，从而绕开穷举。

Phase 1 · LLM
高层模型提议
LLM 依据任务集（目标、初始态、物体语义）以编程格式提出候选动作模型 H_E；用 可靠且完备的 BT 规划算法检验完备性。规划失败 ⇒ 把诊断信息 I_fail 回灌 LLM 再提议。
ctx = 规划上下文 I_fail
Phase 2 · VLM
底层策略采样
VLM（Molmo 取关键点 + cuRobo IK + 夹爪 API）把符号意图翻译成可执行 Python 控制代码 π；在仿真中执行，检验是否达成 sₜ ⊇ pre∪add\del。匹配则 ⟨h,π⟩ 入库。
ctx = 执行上下文 I_e（图像/代码/反馈）
Phase 3 · VLM
跨层精化
若某动作模型 N_max 次都采不到一致策略 ⇒ 判定不一致。融合规划上下文 {I_p} 与执行上下文 {I_e}，让 VLM 诊断根因（漏掉的空间前置、错误的符号效果）并改写出修正后的 h′。
ctx = 规划 {I_p} + 执行 {I_e}

关键公式

H_E = LLM(P, H_P) Eq.2 初始提议
H′ = LLM(P, H_U, I_fail) Eq.3 失败反馈再提议
π = VLM(h, Π_P, I_e) Eq.4 策略采样
h′ = VLM(h, H_U, {I_p}, Π_P, {I_e}) Eq.5 跨层精化
I_fail 里到底装了什么？ 论文说每个失败条目 I_p 封装了关键诊断：不完整 BT 的拓扑草图（BTML）和规划中展开的条件数量（expanded nodes）。这些符号线索帮助 LLM 定位"缺了哪个动作/条件"，从而提出更有希望的动作模型。代码里这一点被原样实现（见下方代码映射）。
Core Algorithm

底层引擎：可靠且完备的 BT 规划

CABTO 阶段 1 评估"完备性"靠的是 BT Expansion 系列算法（OBTEA / HOBTEA，源自 Cai et al.）。其"可靠 + 完备 + 最优"性质来自目标条件回归式扩展 + 优先队列最优搜索：从目标条件出发反向回归，每次只扩展当前最小代价的条件路径，直到某条件被初始状态满足。

状态转移（严格 STRIPS）

# btgym/algos/bt_planning/Action.py  (L118-123)
def state_transition(state, action):
    if not action.pre <= state:
        print('error: action not applicable'); return state
    new_state = (state | action.add) - action.del_set
    return new_state

// 这就是公式 sₜ₊ₖ = sₜ ∪ add(a) \ del(a) 的直接落地

回归扩展 + 支配剪枝（完备性 & 最优性的来源）

# btgym/algos/bt_planning/HOBTEA.py  (回归扩展核心 L132-167，简化)
if not c & ((act.pre | act.add) - act.del_set) <= set():  # 动作对条件 c 有正贡献
    if (c - act.del_set) == c:                       # 且不破坏 c
        c_attr = (act.pre | c) - act.add               # 回归出新条件
        if check_conflict(c_attr): continue           # 剪掉矛盾条件
        # 支配剪枝：已扩展过更弱的条件则跳过
        c_attr_node = Leaf(type='cond', content=c_attr,
                          min_cost=current_mincost + act.cost)
# 用 heapq 按 min_cost 弹出 → 保证输出 minimum-cost BT；c <= start 即找到解

Consistency Check

代码与论文：一致点 & 差异点

✓ 高度一致

  • STRIPS 动作模型 + 可靠完备 BT 回归扩展：Action.py 的 state_transition + OBTEA/HOBTEA 最优扩展，就是 Φ=⟨C,A⟩ 与 BT planning 的实现。
  • 阶段1（提议+I_fail 反馈）：有真实 GPT-3.5/GPT-4o、有无反馈对比 CSV，对应论文表1。
  • 阶段3（跨层精化）：VLM+图像+规划/执行上下文修正 pre/add/del，有真实结果，对应论文表3。
  • 平台与底层组件：单/双臂 Franka 仿真、Molmo、cuRobo 都真实存在。

△ 差异 / 缺口

  • README 略有出入：验证脚本实际默认 obtea（非 HOBTEA）；主仿真是 Franka（dexrl），OmniGibson/Tiago 未与实验主循环完全打通。
  • 阶段2 无端到端主循环：Molmo/cuRobo/IK 都是独立积木，缺少把它们拼成"策略采样+一致性验证"的统一脚本。
  • 表2 的 baseline 缺失：OpenVLA/VoxPoser/ReKep 在仓库中无可跑实现；ASR/CSR/FC 没有专门指标实现（用 success_rate/feedback_times 近似）。
  • "v15" 是论文之外的扩展层：baselines/atoms（4 原子约束）、eval_v15（SR/CR/slope_k、定理1）、docs/*_v15 是博士论文规划与骨架（多为 TODO 与合成数据演示），不应当作 AAAI 论文已完成实验。
